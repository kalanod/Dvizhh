# Учётные записи

`AccountService` — единый бизнес-сервис регистрации, проверки учётных данных,
изменения логина/почты и пароля. HTTP-слой проверяет сессию и источник запроса,
переводит ошибки сервиса в HTTP. `AccountRepository` отвечает за хранение,
а транзакцией управляет request-scoped `Database.session`.
Профили приложения остаются в `backend.UserService`.

Смена пароля из своего профиля проходит по цепочке
UI → `POST /api/personal/password` в backend → `POST /api/auth/password` в auth-api.
Backend делегирует команду и не проверяет и не хеширует пароли.

Тело команды: `current_password`, `new_password` (строки, без обрезки пробелов).
Новый пароль соответствует политике регистрации: `PASSWORD_MIN_LENGTH` (по умолчанию 8)
до 128 символов. Посторонние поля запрещены. Нужны cookie `dvizh_access`,
заголовок `X-Dvizh-Account: 1` и тот же origin при его наличии.
Успех — 204 без тела; неверный текущий пароль — 400 с
`detail: "Invalid current password"`; нет сессии — 401; запрещённый источник — 403;
ошибка формата — 422. Ответы не содержат пароль или хеш.

Сервис блокирует строку аккаунта на время проверки и записи Argon2-хеша,
поэтому параллельная смена не может повторно использовать устаревший хеш.
Уже выданные JWT сохраняют действие до истечения срока; смена пароля меняет
данные для последующих входов, но не завершает существующие сессии.
