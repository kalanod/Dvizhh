# Единое место события и автоматическое местное время

В редакторе события одно поле «Адрес или заведение». Отдельных полей «Место»,
«Город» и ручного IANA-пояса нет. Формат входного текста не ограничивается
почтовым адресом: это может быть название заведения, адрес или описание встречи.

## Поисковый текст и структурированное место

Текст ввода нельзя надёжно разобрать регулярным выражением на город, улицу,
заведение и номер дома. Поэтому он является поисковым запросом или описанием,
а структурированные компоненты берутся только из ответа геокодера либо из
сохранённого места события. Это два явно различимых состояния редактора:

```ts
type EventPlaceValue =
    | { kind: "text"; text: string }
    | { kind: "resolved"; text: string; location: EventLocationInput };
```

`text` — строка, которую видит пользователь. В состоянии `resolved` это подпись
для показа, а `location` — канонический снимок данных. Подпись не разбирается
обратно на поля. Разные представления не являются двумя источниками места:
показ строится из канонического снимка, а редактирование строки инвалидирует его.

- Ручной ввод: при сохранении обрезаются крайние пробелы; `address_line` содержит
  текст, `name`, `city`, `latitude`, `longitude` равны `null`. Город профиля не
  подставляется в адрес события. Новый ручной текст ограничен 500 символами.
- Выбор адреса/заведения: геокодер возвращает структурированные имя, адрес, город
  и WGS84-координаты. Город берётся из `Address.Components` с kind `locality`,
  а не выделяется из строки адреса. Выбранное заведение сохраняет своё имя.
- Клик на карте/геолокация: точные координаты точки сохраняются с шестью знаками,
  даже если геокодер вернул центр соседнего здания. Если обратное геокодирование
  недоступно, остаётся точка без выдуманного адреса/города.
- Любое изменение текста после выбора сбрасывает весь снимок, включая старые
  имя, город и координаты, и отменяет устаревший запрос геокодера. Запоздавший
  ответ не может вернуть прежние геоданные.
- При редактировании старого события исходный снимок сохраняется без потерь,
  пока пользователь не изменил место. Это также поддерживает старые адреса
  без координат и ранее сохранённые длинные адресные строки.

Транспорт событий и хранение остаются совместимыми: `location` содержит только
`name`, `city`, `address_line`, `latitude`, `longitude`; обе координаты либо
присутствуют вместе, либо равны null. Для OFFLINE/HYBRID нужен адрес/описание
или точка. Для ONLINE `location` равен null. URI организации нужен для поиска,
но в этом изменении не вводится новый формат хранения идентификаторов провайдера.
Новой миграции не требуется.

Нормализация и отображение места сосредоточены в `eventPlace.ts` и
`formatLocationLabel`: форма не хранит отдельные редактируемые копии города,
названия, адреса и координат. Ошибка карты/отсутствие ключей не запрещают ручной ввод.
Во время разрешения выбора сохранение ожидает завершения запроса.

## Определение пояса

`POST /api/maps/timezone` — операция чтения, ответ `Cache-Control: no-store`:

```json
{
  "place": {"latitude": 35.6762, "longitude": 139.6503},
  "user_id": null,
  "device_timezone": "Europe/Moscow"
}
```

`place` и `user_id` могут быть null. Тело не принимает посторонние поля.
Координаты — конечные числа WGS84: широта −90…90, долгота −180…180.
`device_timezone` — валидное IANA-имя из `Intl.DateTimeFormat().resolvedOptions()`;
UTC используется только если браузер не сообщил пояс.

Ответ:

```json
{"timezone": "Asia/Tokyo", "source": "place", "city": null}
```

`EventTimezoneService` выбирает первый успешно определённый вариант:

1. Координаты выбранного места события, `source: place`.
2. Парные координаты профиля организатора, `source: profile_coordinates`.
3. Город профиля, геокодированный в населённый пункт, `source: profile_city`.
4. Пояс устройства, `source: device` — согласованный резерв при недостатке данных.

Для координат используется офлайн `timezonefinder.timezone_at_land`.
Координаты в океане без определённой наземной зоны не превращаются в фиктивный
часовой пояс места. Пустой/недоступный профиль, неподходящий ответ геокодера,
недоступность провайдера или отсутствие ключа продолжают цепочку fallback.
IANA проверяется через ZoneInfo. Определение по координатам и сетевой запрос
выполняются вне event loop; данные поясов не скачиваются при каждом запросе.

Карты используют существующую модель идентификатора профиля: это пока не замена
задаче авторизации событий. `user_id` в запросе — тот же ID организатора, который
использует текущий API; он не создаёт новых прав на изменение профиля/мероприятия.
Сервер читает город из профиля, не принимает его свободной строкой от формы.

## Дата и редактирование

Datetime-local — локальные часы события. При изменении места введённые часы
сохраняются, но перевод в UTC выполняется в новом автоматически выбранном поясе.
Например, 10:00 в Токио означает 01:00 UTC, а 10:00 в Москве — 07:00 UTC.
Несуществующее время при переходе на летнее время отклоняется текущей валидацией.

Редактор старого события начинает с сохранённых timezone и UTC-момента. До изменения
места автоматическая переоценка пояса не сдвигает существующее событие; смена
только формата также не меняет его момент начала.
На API по-прежнему отправляются aware `starts_at`/`ends_at` и IANA `timezone`;
старые клиенты API сохраняют прежний контракт.

Форма сообщает источник местного времени без редактируемого IANA-поля.
Во время определения пояса сохранение ожидает результат. Если сам endpoint
недоступен, форма явно предупреждает о переходе к поясу устройства. Устаревшие
запросы отменяются, старый результат не применяется к новому месту.

## Зависимости и запуск

`timezonefinder` объявлен в backend/pyproject.toml, точные версии и данные поясов
зафиксированы в backend/uv.lock. Dockerfile устанавливает их через `uv sync --locked`
при сборке; ручная установка в работающий контейнер не нужна.

```shell
docker compose build backend web-app
docker compose up -d --no-deps backend web-app
```

Проверять нужно не только сборку, но и healthcheck/API. Если nginx держит адрес
старого пересозданного upstream, выполните `docker compose restart nginx` после
запуска web-app. Volumes и данные при обновлении не удаляются.

Ссылки на форматы провайдеров: [ответ геокодера Яндекса](https://yandex.com/maps-api/docs/geocoder-api/response.html),
[API timezonefinder](https://timezonefinder.readthedocs.io/en/latest/1_usage.html).
Тесты без ключей проверяют офлайн географию и обработку ответов; они не подтверждают
актуальные права конкретного ключа на геокодирование или поиск организаций.
