# Контракт динамических настроек v2

Статус: реализован. Страница `/admin_panel` и оба settings endpoint доступны
**только администратору**. Источник структуры — backend:
`document → tabs → cards → rows → elements`.

Авторитетные модели: `backend/src/dvizh_backend/dto/settings.py` (также OpenAPI)
и `web-app/src/models/settings.ts`. Runtime-проверка JSON: `web-app/src/api/settings.ts`.
v2 заменяет v1: `tab.rows` заменён на `tab.cards`, плоский `values` команды —
на `rows`, ответ дополнен `applied_rows`. Клиент и сервер обновляются вместе;
v1 отклоняется, а не переинтерпретируется.

## Получение страницы

`GET /api/settings` → `200`, `Cache-Control: no-store`.
Cookie `dvizh_access` проверяется через auth-api, роль проверяется при каждом запросе.

```json
{
  "schema_version": 2,
  "tabs": [{
    "id": "categories", "label": "Категории",
    "cards": [{
      "id": "categories.create", "title": "Новая категория",
      "rows": [{"id": "category.create", "elements": [
        {"id": "name", "type": "input", "label": "Название", "value": "",
         "input_type": "text", "required": true, "max_length": 120},
        {"id": "color", "type": "input", "label": "Цвет", "value": "#808080",
         "input_type": "text", "required": true, "pattern": "#[0-9A-Fa-f]{6}", "max_length": 7},
        {"id": "sort_order", "type": "input", "label": "Порядок", "value": "0",
         "input_type": "text", "required": true, "pattern": "-?[0-9]+", "max_length": 11}
      ]}],
      "actions": [{"id": "save", "type": "button", "label": "Создать",
                   "action_id": "category.create", "tone": "primary",
                   "validate_fields": true, "rows": "all"}]
    }, {
      "id": "categories.edit", "title": "Категории", "rows": [],
      "actions": [{"id": "save", "type": "button", "label": "Сохранить все",
                   "action_id": "category.save", "tone": "primary",
                   "validate_fields": true, "rows": "changed"}]
    }]
  }]
}
```

В примере список существующих категорий пуст; сервер добавляет реальные строки.
Порядок массивов задаёт порядок отображения.

| Узел | Поля |
| --- | --- |
| document | `schema_version: 2`, `tabs[]` |
| tab | `id`, `label`, `cards[]` |
| card | `id`, необязательные `title`/`description`, `rows[]`, `actions[]` |
| row | `id`, `elements[]` |

Название раздела используется только во вкладке слева. В правой section нет
отдельного заголовка/описания раздела: весь контент размещается в карточках.
Карточка может иметь свой заголовок, описание, список строк и несколько действий.
Допустимы карточки без заголовка и пустые массивы вкладок, карточек, строк и действий.

IDs вкладок уникальны в документе, карточек — среди всех карточек, строк — среди
всех строк. IDs элементов уникальны внутри строки, IDs действий карточки — внутри
`card.actions`. `action_id` уникален среди всех кнопок документа.
IDs стабильны: латиница, цифры, `_`, `.`, `:`, `-`, от 1 до 200 символов.

Страница занимает высоту окна без внешней прокрутки. Прокручивается только правая
section: вертикально — карточки со списками, горизонтально — длинные строки
на узком экране. Элементы строки выровнены в один ряд без переноса.

## Элементы и действия

Все элементы имеют `id` и дискриминатор `type`:

| type | Обязательные поля ответа | Необязательные поля |
| --- | --- | --- |
| `text` | `text: string`, `tone: normal \| muted` | — |
| `input` | `label`, `value: string`, `input_type: text \| password`, `required: boolean` | `min_length`, `max_length`, `pattern`, `hint`, `matches`, `autocomplete` |
| `select` | `label`, `value: string`, `required: boolean`, `options: [{value, label}]` | — |
| `toggle` | `label`, `value: boolean` | `hint` |
| `button` | `label`, `action_id`, `tone: primary \| secondary \| danger`, `validate_fields: boolean`, `rows: all \| changed` | `confirmation: string` |

`card.actions` содержит только button. `row.elements` может содержать все пять типов.
Кнопка строки относится только к своей строке и имеет `rows: all`.
Кнопка карточки относится только к строкам своей карточки:

- `rows: all` — отправить все редактируемые строки; создание и пароль.
- `rows: changed` — только строки с фактическими изменениями. При отсутствии
  изменений кнопка отключена; возврат поля к исходному значению убирает изменение.

Отправляемая строка содержит **все** её input/select/toggle, а не только изменённые
поля. Text/button в значения не входят. Строки только с текстом не отправляются
действиями карточки. `validate_fields: true` проверяет все отправляемые строки;
`false` используется при удалении: незаписанный неверный ввод не мешает удалению.
Цвет кнопки не задаёт поведение. `confirmation` требует подтверждения перед POST.

`min_length`/`max_length` — неотрицательные целые. `pattern` — полное совпадение
в подмножестве выражений, совместимом с Python и HTML/JS Unicode Sets (`v`).
`matches` — ID другого input той же строки; значения должны совпадать.
Select имеет уникальные `options[].value`; текущее значение входит в options,
кроме пустого значения необязательного select. Браузер не заменяет серверную проверку.

Подсказка input появляется при фокусе как tooltip с `aria-describedby`, Escape
скрывает её. Она находится поверх страницы, не меняет геометрию строки и не
обрезается секцией; при нехватке места сверху выводится ниже.
Password всегда возвращается со значением `""`. Пароли/хеши не возвращаются
в документе, сообщениях и ошибках. Секреты — локальное состояние карточки,
очищаются после запроса и ухода со вкладки, не переносятся при обновлении схемы
и не сохраняются в localStorage. Остальные черновики — только память страницы.

HTML, JS, URL запросов, CSS и имена клиентских функций не передаются.
Frontend выводит обычный экранированный React-текст и использует пять известных типов.

## Выполнение действия

`POST /api/settings/actions/{action_id}`, например `category.save`:

```json
{
  "schema_version": 2,
  "rows": {
    "category.00000000-0000-0000-0000-000000000001": {
      "name": "Первое название", "color": "#123456", "sort_order": "0"
    },
    "category.00000000-0000-0000-0000-000000000002": {
      "name": "Второе название", "color": "#654321", "sort_order": "1"
    }
  }
}
```

Версия — строго целое `2`, лишних полей тела нет. `rows` содержит 1–500 строк;
в каждой не более 30 полей, значения строго string или boolean. UUID/select
и числовой ввод передаются строками, toggle — boolean.
`sort_order`: PostgreSQL INTEGER, от −2147483648 до 2147483647.

POST заново проверяет роль, whitelist текущего документа, принадлежность строк
карточке и точный набор полей. Чужие карточки/строки, создание внутри edit-пакета
и пароль в пакете каталога запрещены. Кнопка строки требует ровно свою строку;
`all` — весь редактируемый набор; `changed` — непустое подмножество своей карточки.

Нужны cookie `dvizh_access`, `X-Dvizh-Admin: 1`, `X-Dvizh-Account: 1` и совпадающий
с Host Origin при его наличии. При передаче пароля auth-api backend сохраняет
исходные Host/Origin, cookie и X-Dvizh-Account. Скрытие вкладок не является защитой.

Успех: `200`, `Cache-Control: no-store`:

```json
{
  "schema_version": 2,
  "message": "Изменения сохранены.",
  "applied_rows": [
    "category.00000000-0000-0000-0000-000000000001",
    "category.00000000-0000-0000-0000-000000000002"
  ],
  "document": {"schema_version": 2, "tabs": []}
}
```

`document` — полный актуальный документ, не JSON patch (в примере вкладки опущены).
`applied_rows` — ровно IDs отправленных строк без повторений в порядке запроса.
Удалённый ID уже может отсутствовать в новом документе. UI очищает только черновики
подтверждённых строк; независимые изменения других карточек сохраняются, пока поля
и варианты select существуют. Неизменённые значения берутся из свежего документа.
Посторонние или неполные applied_rows считаются ошибкой протокола.

Общее сохранение каталога — **один запрос, одна транзакция backend**. Все поля
и типизированные DTO проверяются до первой записи. Доменная ошибка в любой строке
прерывает запрос и откатывает весь пакет. Частичных успешных ответов нет.
Создание и удаление — самостоятельные действия. Пароль — отдельная карточка
и запрос: запись auth-api нельзя откатить транзакцией backend.

## Реестр действий v2

Frontend считает action ID непрозрачным; серверный реестр:

| action_id | Область | Поля строки |
| --- | --- | --- |
| `security.password` | карточка `security.password`, all | `current_password`, `new_password`, `confirm_password` |
| `category.create` | карточка `categories.create`, all | `name`, `color`, `sort_order` |
| `category.save` | карточка `categories.edit`, changed | те же |
| `category.delete.<uuid>` | строка `category.<uuid>`, all | те же, значения игнорируются |
| `tag.create` | карточка `tags.create`, all | `name`, `slug`, `category_id`, `is_active`, `sort_order` |
| `tag.save` | карточка `tags.edit`, changed | `name`, `category_id`, `is_active`, `sort_order` |
| `tag.delete.<uuid>` | строка `tag.<uuid>`, all | те же, значения игнорируются |

Сущности выбираются по серверным IDs строк/действий. TagService владеет бизнес-
правилами/хранением каталога; SettingsService строит схему, валидирует команды UI
и делегирует операции. Slug неизменяем. Категорию с тематиками и используемую тематику
нельзя удалить; используемую тематику можно отключить. Без категорий карточка создания
тематики содержит текстовую подсказку и не содержит действия создания.

Пароль меняется только у собственного аккаунта администратора через
`UserService → AccountGateway → auth-api.AccountService`. Проверка текущего пароля
и Argon2 принадлежат auth-api, политика нового пароля совпадает с регистрацией.
Сервер может требовать больше 8 символов. Выданные JWT действуют до истечения срока.

## Ошибки и расширение

Ошибка: `{"detail": "Безопасное сообщение"}`.
`400` — неверный текущий пароль; `401` — нет сессии; `403` — нет роли/запрет записи;
`404` — действие/сущность исчезли; `409` — доменный конфликт; `422` — неверная
версия/структура/значения; `503` — auth-api недоступен. Валидация не возвращает
input/ctx, cookie, пароли и хеши.

После `401/403` формы закрываются, черновики сбрасываются и схема запрашивается
снова с серверной проверкой доступа. Неизвестная версия/тип блокируют весь документ.
Новые дополнительные поля ответа можно игнорировать; ломающие изменения требуют
новой schema_version. Пока идёт POST, действия и переключение вкладок заблокированы.
Автосохранения/автоповтора нет. При потере ответа или 5xx результат может быть
неизвестен: записи блокируются до перезагрузки страницы. Кнопки обновления нет.
Отмена fetch не отменяет принятую команду. Конкурентное редактирование сохраняет
семантику доменных API: последняя успешная запись побеждает, schema_version не
является версией данных.

Для новой настройки добавьте карточку/строки и действия в SettingsService,
типизированную команду и проверки прав. Для пяти существующих типов элементов
менять React не требуется. Новый тип требует обновления Pydantic/TS, парсера,
рендерера и тестов. Документ UI не хранит произвольные настройки или секреты.
