# Синтетические мероприятия и участие

[Основной README](../README.md) · [50 тестовых пользователей](test-users.md)

Генератор [seed_demo_events.py](../backend/scripts/seed_demo_events.py) создаёт
набор `01b944fc` для проверки ленты, фильтров, карточек, календаря и заявок.
Все мероприятия явно помечены как синтетические: реальные встречи не проводятся,
адреса демонстрационные, ссылки онлайн-встреч ведут на `example.com`.
Обложки и медиафайлы не создаются.

## Результат загрузки

14 ноября 2026 года набор создан в локальной БД и на удалённом сервере
в проекте `/srv/projects/dvizh`: по 300 мероприятий, 1696 записей `GOING`
и 350 заявок `REQUESTED` в каждом окружении. Даты начала — с 15 ноября 2026
по 12 февраля 2027 года. UUID мероприятий и пользователей в окружениях различаются.

После загрузки проверены поля мероприятий, организаторы, статусы участия и
публичная лента. Повторный запуск генератора не добавил дубликатов.
На сервере сохранены два ранее существовавших мероприятия; `.env` не изменялся.

| Мероприятия каждого организатора | 6 |

| Записи участников со статусом «иду» (`GOING`) | 1696 |
| Ожидающие решения заявки (`REQUESTED`) | 350 |

У открытых мероприятий — от 4 до 10 участников. У каждого мероприятия с заявками
3 заявки одобрены организатором, ещё от 2 до 5 ожидают решения. Организатор
не записывается на собственное мероприятие. Участники распределены между всеми
50 пользователями; это 2046 записей участия, а не 2046 разных людей.
Лимит мероприятия — от 12 до 28 мест; одобренные участники его не превышают.

Тематик 15: музыка, фотография, настольные игры, спорт, книги, наука, кино,
танцы, кулинария, языки, рисунок, технологии, походы, театр и волонтёрство.
Названия, описания и программа встреч на русском языке.
По 60 мероприятий связаны с Санкт-Петербургом, Москвой, Казанью,
Новосибирском и Екатеринбургом. У онлайн-мероприятий город указан в названии,
физического места нет. Время учитывает часовой пояс соответствующего города.

Каждое мероприятие имеет уникальный префикс названия
`[DEMO-01b944fc-001]` … `[DEMO-01b944fc-300]` и теги `synthetic`,
`dvizh-demo-01b944fc`, а также тематический тег. Фильтр API:
`GET /api/events?tag=dvizh-demo-01b944fc&limit=100` (для всех записей нужны страницы).

## Даты и повторный запуск

Мероприятия распределяются с завтрашнего дня до 90-го дня относительно даты
первого запуска в часовом поясе Москвы. Если набор уже существует частично,
опорная дата восстанавливается из даты создания первого мероприятия набора.
Повторный запуск не переносит существующие мероприятия на новые даты.

Генератор не создаёт новых пользователей: должны существовать ровно профили
`demo_01b944fc_01` … `demo_01b944fc_50` в активном состоянии.
UUID берутся из выбранного окружения, поэтому локальная и серверная БД независимы.

Сначала выполняется проверка существующих записей и план без записи в БД.
Создание событий, запись участников и одобрение заявок выполняются обычными API,
с проверками доменной логики и записью истории статусов. SQL используется
только для чтения профилей, обнаружения набора и итоговой сверки участия.

При повторном `--apply` существующие мероприятия не дублируются, добавляются
только недостающие записи набора. Если мероприятие или участие вручную изменены
и конфликтуют с планом, генератор останавливается, сохраняя данные.
Выполненные до ошибки API-запросы остаются в БД; после устранения причины запуск
можно повторить. Одновременно запускать несколько копий генератора нельзя.

## Запуск в выбранном окружении

Команды выполняются из корня проекта в Bash на хосте с запущенным Compose.
Они используют уже установленный пакет и настройки контейнера backend,
не требуют публикации внутренних сервисов или изменения `.env`.

Проверка и план без записи:

```bash
docker compose exec -T backend python - < backend/scripts/seed_demo_events.py
```

Создание набора в выбранной БД:

```bash
docker compose exec -T backend python - --apply < backend/scripts/seed_demo_events.py
```

Проверка полного существующего набора без записи:

```bash
docker compose exec -T backend python - --verify-only < backend/scripts/seed_demo_events.py
```

В конце выводится JSON со счётчиками мероприятий и статусов участия.
`--verify-only` требует наличие всех 300 мероприятий, соответствие их полей
плану и точное соответствие записей участия в БД. Пароли, ключи и настройки
подключения в отчёт не включаются.
