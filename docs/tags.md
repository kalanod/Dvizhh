# Каталог тегов и категории

Теги управляются администратором и объединены в категории. Один тег относится к одной
категории; цвет принадлежит категории. Событию можно назначить от нуля до пяти тегов.
Создание события не создаёт новые теги.

## Публичный API

`GET /api/tags` возвращает полный каталог активных тегов, сгруппированный по категориям:

```json
[
  {
    "id": "category-uuid",
    "name": "Природа",
    "color": "#238636",
    "sort_order": 0,
    "tags": [
      {
        "id": "tag-uuid",
        "category_id": "category-uuid",
        "slug": "hiking",
        "name": "Походы",
        "is_active": true,
        "sort_order": 0
      }
    ]
  }
]
```

При создании и редактировании события передавайте `tag_ids: UUID[]` вместо `tags: string[]`.
Ответ события содержит `tags` с полями `id`, `slug`, `name`, `is_active` и объектом
`category` (`id`, `name`, `color`, `sort_order`). Фильтрация ленты: `GET /api/events?tag_id=UUID`.
Название можно менять, не меняя ID, slug и связи с событиями.

## Администрирование

Начальный аккаунт администратора — `admin:admin`. При необходимости роль меняется
напрямую через `accounts.role_id` в базе auth-api; консольных команд назначения ролей нет.
Подробности — в [документации ролей](roles.md).

Администратор входит через обычный `POST /api/auth/login`. Админские запросы используют
cookie `dvizh_access`; backend проверяет текущие права через `/api/auth/me` auth-сервиса.
Отзыв прав действует при следующем запросе, не требуя истечения JWT.
Без авторизации возвращается 401, без прав администратора — 403, при отказе auth-сервиса — 503.
Переданный клиентом ID пользователя не подтверждает права.

Для изменяющих запросов обязателен заголовок `X-Dvizh-Admin: 1`. Запросы браузера с чужим
Origin отклоняются. Страница `/admin_panel` пока содержит только заголовок;
ручки доступны через HTTP-клиент и Swagger с авторизованной cookie.

| Запрос | Назначение |
| --- | --- |
| `GET /api/admin/tags` | Полный каталог, включая отключённые теги |
| `POST /api/admin/tag-categories` | Создать категорию: name, color, sort_order |
| `PATCH /api/admin/tag-categories/{id}` | Изменить категорию |
| `DELETE /api/admin/tag-categories/{id}` | Удалить пустую категорию |
| `POST /api/admin/tags` | Создать тег: category_id, slug, name, is_active, sort_order |
| `PATCH /api/admin/tags/{id}` | Изменить название, категорию, активность или порядок |
| `DELETE /api/admin/tags/{id}` | Удалить тег, не связанный с событиями |

Цвет категории — `#RRGGBB`. Slug уникален и не меняется через PATCH.
Используемый тег нельзя удалить (409), но можно отключить через `is_active: false`.
Он останется на существующих событиях и будет недоступен для нового назначения.
Редактирование события позволяет оставить ранее назначенный отключённый тег или снять его.
Категория с тегами не удаляется (409): сначала перенесите или удалите её теги.

## Запуск и миграции

```bash
docker compose up -d --build
```

Миграции обоих API применяются при запуске контейнеров. Новые таблицы: `tags`,
`tag_categories`, `event_tags`. Существующие связи сохраняются; прежние свободные теги
попадают в категорию «Прочее». Начальные категории и теги добавляет миграция; их можно
изменять админскими ручками. Рекомендательная модель не меняется этим переходом.

На сервере задайте `AUTH_JWT_SECRET` в `.env` случайной строкой длиной не менее 32 символов.
Секрет не включайте в Git. Без значения сервис создаёт случайный ключ на время процесса:
локальный запуск работает, но после перезапуска auth-сервиса потребуется повторный вход.
