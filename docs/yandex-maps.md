# Яндекс Карты: место события

Для недельного прототипа выбран бесплатный API Яндекса. Адрес, город и координаты сохраняются в существующей таблице `locations` на срок работы прототипа, в пределах разрешённых 30 дней. Отдельного хранилища геокодирования, автоматического обновления и фоновых проверок срока нет. После завершения прототипа полученные данные нужно удалить в пределах этого срока, включая копии БД.

## Подключение

В [кабинете разработчика](https://developer.tech.yandex.ru/) подключите JavaScript API, API Геосаджеста и HTTP Геокодер. Запишите ключи в корневой `.env`:

```dotenv
YANDEX_MAPS_API_KEY=ключ_Javascript_API
YANDEX_SUGGEST_API_KEY=ключ_Геосаджеста
YANDEX_GEOCODER_API_KEY=ключ_HTTP_Геокодера
```

Если HTTP Геокодер подключён к тому же ключу, что JS API, третью переменную можно оставить пустой. Ключ JS API доступен браузеру по назначению; отдельные серверные ключи не передаются фронтенду.

Для JS API v3 заполните ограничения HTTP Referer: разрешите `localhost:8080` и домен сайта; при разработке через Vite также `localhost:5173` и используемый адрес `127.0.0.1`. Геосаджест и Геокодер вызываются backend с передачей Referer исходной страницы. Настройте их ключи под этот способ вызова. Активация ключа может занимать до 15 минут.

Запуск после заполнения `.env`:

```shell
docker compose up --build
```

Сайт: **http://localhost:8080/**. Ключи читаются backend при запуске; пересобирать JS ради изменения ключа не требуется. Без ключей остальное приложение работает, а на месте карты отображается сообщение о недоступности.

## Поведение

- В редакторе OFFLINE/HYBRID показывается адрес с подсказками и интерактивная карта. Для ONLINE остаётся ссылка на трансляцию.
- Подсказки запрашиваются от трёх символов с задержкой 350 мс. Город учитывается при поиске. Поддерживаются стрелки, Enter и Escape.
- Можно искать заведения по названию и типу, например «антикафе». После определения своего местоположения выдача получает приоритет в окрестности пользователя; иначе учитывается последняя выбранная точка или город. Это приоритет, а не жёсткое ограничение районом; порядок результатов Яндекса сохраняется.
- Для выбора заведения нужен API Поиска по организациям, подключённый к ключу Геокодера. Если у него отдельный ключ, задайте `YANDEX_SEARCH_API_KEY` в `.env`. Геосаджест предлагает организации и адреса, а Поиск по организациям получает точную точку выбранного заведения по `uri` и его название.
- Выбор адресной подсказки вызывает Геокодер по её `uri` и ставит метку. Выбор заведения заполняет название площадки и адрес. Кнопка «Найти» открывает список подходящих адресов и заведений; стрелки и Enter выбирают конкретный вариант.
- Клик по карте или перетаскивание метки выбирают точку и определяют адрес. Координаты клика сохраняются точно, без замены центром ближайшего здания.
- Кнопка «Моё местоположение» запрашивает координаты устройства через браузер, устанавливает метку и определяет адрес. Запрос выполняется только по нажатию; нужен доступ к геолокации, HTTPS или localhost. Отказ в доступе не меняет ранее выбранное место.
- Изменение текста адреса отменяет старый запрос и сбрасывает прежнюю точку. Начальный центр карты не сохраняется как место события.
- Просмотр события показывает карту с сохранённой меткой и переход «Открыть в Картах». При просмотре повторное геокодирование не выполняется.

Данные сохраняются через существующий API событий: `name`, `city`, `address_line`, `latitude`, `longitude`. Координаты — WGS84 с шестью знаками после запятой. Для карты используется порядок `[longitude, latitude]`. Миграция схемы не нужна.

Служебные endpoints: `GET /api/maps/config`, `GET /api/maps/suggest?text=...&city=...`, `GET /api/maps/geocode?query=...` или `?uri=...`. Геоданные не добавляются в HTTP-кэш; ответы провайдера целиком не сохраняются.

## Диагностика

Если адрес выбирается успешно, а выбор заведения возвращает 401/403, проверьте доступ ключа к **API Поиска по организациям**. Геосаджест может показывать названия заведений без доступа к этому отдельному продукту. В `.env` задайте `YANDEX_SEARCH_API_KEY` ключом, привязанным к активному API Поиска по организациям, затем выполните `docker compose up --build`. Если отдельный ключ не задан, используется ключ Геокодера, а при его отсутствии — ключ JS API. В логах `Yandex organization lookup: key_source=...` видно имя используемой переменной без значения ключа.

Ошибки загрузки SDK и создания карты выводятся в консоль браузера с префиксом `[Yandex Maps]` и передаются через `POST /api/maps/client-error` в логи backend. Запись содержит этап, адрес источника страницы и состояние подключения браузера. Значения ключей скрываются. Отказы серверного Геокодера и Геосаджеста записываются с HTTP-статусом и сообщением Яндекса.

После обновления кода пересоберите контейнеры командой `docker compose up --build`, обновите страницу и смотрите `docker compose logs -f backend`. Например, `stage=script_load` означает ошибку загрузки SDK, `stage=sdk_ready` — отказ инициализации SDK, `stage=map_init` — ошибку создания карты. У `script.onerror` нет HTTP-статуса; точный статус исходного запроса виден в браузере: F12 → Network → `api-maps.yandex.ru/v3/`.

## Условия и документация

Проверено 4 ноября 2026 года. Суточный бесплатный лимит Геосаджеста — 1000 запросов, Геокодера — 1000 запросов. Несколько запросов во время набора адреса расходуют несколько единиц лимита. Бесплатное использование предполагает общедоступный проект и сохранение обязательных элементов Яндекса на карте. Возможность кэширования до 30 дней не означает права бессрочного хранения или произвольного использования данных вне картографического сценария; эта интеграция предназначена для выбора и отображения места.
