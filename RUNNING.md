## 0. Посмотреть сайт

Что нужно установить заранее:

- [Docker Desktop](https://www.docker.com/products/docker-desktop/), запущенный
  (в окне Docker Desktop написано *Engine running*);
- [Node.js 22+](https://nodejs.org/), только для варианта Б.

### Вариант А: просто открыть сайт

Подходит, чтобы посмотреть, как сайт выглядит и работает целиком.

1. Один раз скопировать `.env.example` в `.env` (в корне репозитория).
2. Из корня репозитория запустить:

   ```shell
   docker compose up -d --build
   ```

   Первый запуск занимает несколько минут: собираются образы всех сервисов.

3. Открыть в браузере `http://localhost:8080`
   (или `http://localhost:<NGINX_PORT>`, если порт в `.env` изменён).
4. Войти через тестового пользователя (см. [Вход в приложение](#4-вход-в-приложение))
   или зарегистрироваться.

Если после правок в коде сайт не изменился, пересоберите фронтенд:
`docker compose up -d --build web-app`, затем `Ctrl+F5` в браузере.

### Вариант Б: править дизайн и сразу видеть изменения

Подходит для работы над визуалом: страница обновляется сама при сохранении файла,
пересобирать Docker не нужно. Данные (события, пользователи) берутся из Docker.

1. Запустить backend и базы в Docker (как в варианте А):

   ```shell
   docker compose up -d --build
   ```

2. Один раз создать файл `web-app/.env.development.local` с адресом nginx
   (порт как в `NGINX_PORT`):

   ```shell
   BACKEND_URL=http://127.0.0.1:8080
   ```

3. В отдельном терминале запустить dev-сервер фронтенда:

   ```shell
   cd web-app
   npm ci        # только при первом запуске или после изменения package.json
   npm run dev
   ```

4. Открыть `http://localhost:5173`.

Теперь правки в `web-app/src` (компоненты, `styles/globals.css`, картинки
в `assets/images`) видны в браузере сразу после сохранения.

## 1. Запуск в Docker

### Первый запуск

1. Скопировать `.env.example` в `.env` и заменить пароли.
2. Из корня репозитория запустить проект:

   ```shell
   docker compose up --build
   ```

3. Открыть `http://localhost:8080`.

Миграции базы применяются автоматически при старте контейнера `backend`.

> Порт nginx задаётся переменной `NGINX_PORT` в `.env` (по умолчанию `8080`).
> Если порт `8080` занят, укажите другой, например `NGINX_PORT=8088`,
> и используйте его во всех адресах ниже.

### Адреса сервисов

| Сервис | Адрес |
|---|---|
| Приложение | `http://localhost:8080` |
| Проверка API | `http://localhost:8080/api/health` |
| Swagger backend | `http://localhost:8080/api/docs` |
| Консоль MinIO | `http://localhost:9001` |

Проверка API из терминала:

```shell
curl http://localhost:8080/api/health
```

### Обновление после изменений в коде

Фронтенд собирается внутрь образа при сборке, поэтому правки в коде сами
в контейнер не попадают. После изменений пересоберите нужный сервис:

```shell
docker compose up -d --build web-app
```

Если браузер показывает старую версию, обновите страницу без кэша (`Ctrl+F5`).

### Остановка

```shell
docker compose down
```

### Обновление существующих БД

Нужно только при обновлении со старых версий; на новой БД всё создаётся автоматически.

**Пользователь `recsys_reader`.** Если база создана до появления этого пользователя,
примените права чтения:

```shell
docker compose up -d --build postgres pgvector
docker compose exec -T postgres sh /docker-entrypoint-initdb.d/01-recsys-reader.sh
```

Пароль пользователя задаётся через `RECSYS_READER_PASSWORD` в `.env`.

**Таблица `event_embeddings`.** Если pgvector инициализирован до её добавления,
примените текущую схему:

```shell
docker compose exec -T pgvector sh -c 'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB" -f /docker-entrypoint-initdb.d/01-vector.sql'
```

После этого запустите остальные сервисы через `docker compose up --build`.
Повторное применение этих команд сохраняет данные; удалять volumes не требуется.

## 2. Локальная разработка Python-сервисов

Команды выполняются из каталога нужного сервиса, например `backend`.

### Проверки и тесты

```shell
uv sync --locked
uv run ruff check .
uv run pytest
```

### Запуск backend

```shell
uv run uvicorn dvizh_backend.main:app --reload --port 8000
```

Swagger: `http://localhost:8000/api/docs`.

Без PostgreSQL backend всё равно стартует и показывает Swagger, но запросы к данным
вернут 500.

### Миграции

Таблицы создаются миграциями Alembic:

```shell
uv run alembic upgrade head
```

### Зависимости

Добавление зависимости и обновление lock-файла:

```shell
uv add package-name
```

## 3. Локальная разработка фронтенда

Нужен Node.js 22+. Команды выполняются из `web-app`.

### Команды

```shell
npm ci          # установка зависимостей
npm run dev     # dev-сервер на http://localhost:5173, изменения видны сразу
npm run lint    # проверка ESLint
npm run build   # сборка в web-app/dist
```

### Подключение к backend

Dev-сервер проксирует `/api` в backend. По умолчанию это `http://localhost:8000`
(локальный backend, см. [Запуск backend](#запуск-backend)).

Чтобы работать с API из Docker, укажите адрес nginx (порт из `NGINX_PORT`):

```shell
BACKEND_URL=http://localhost:8080 npm run dev
```

Адрес можно сохранить в `web-app/.env.development.local` (файл не попадает в git):

```shell
BACKEND_URL=http://127.0.0.1:8080
```

> Ошибка `http proxy error ... ECONNREFUSED` в консоли Vite означает, что backend
> по этому адресу не запущен: проверьте, что Docker работает и порт совпадает с `NGINX_PORT`.

## 4. Вход в приложение

Авторизации пока нет: при регистрации создаётся профиль через `POST /api/users`,
а вход выполняется по ID профиля (он показан на странице профиля).

Тестовый пользователь:

| Поле | Значение |
|---|---|
| Ник | `admin` |
| Имя | `admin` |
| ID | `6c0a9fe0-bdd6-4f24-b0f8-1d626a252f4b` |
