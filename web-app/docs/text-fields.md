# Поля ввода

Общие `Input` и `Textarea` используют Material UI `TextField` и `Tooltip`.
Внутри `FormField` подпись берётся из контекста и плавает внутри поля высотой
56 px. Без `FormField` используется компактное поле 41 px с обычным placeholder.
Вариант можно явно выбрать через `variant="floating" | "compact"`.
Многострочные поля сохраняют `rows`, поля дат всегда показывают поднятую подпись.

Локальные ограничения задаются стандартными `required`, `minLength`, `maxLength`,
`pattern`, `type`, `min`, `max`, `step`. Дополнительное правило: `validate(value)`
возвращает текст ошибки либо `null`. Непустое корректное поле формы имеет зелёную
обводку; ошибка — красную. Пустое нетронутое поле нейтрально. Подсказка появляется
над полем при фокусе, статус доступен скринридеру. Ошибка задаёт native customValidity;
серверная проверка при сохранении остаётся обязательной.

`validateAsync(value, signal)` вызывается после 350 ms без ввода и только после
успешной локальной проверки. Передавайте стабильную функцию (`useCallback` для
зависимостей). Смена значения отменяет запрос; ответ другого значения игнорируется.
Во время проверки и при сетевой ошибке зелёная обводка не показывается.
`successMessage` позволяет сообщить результат, например «Никнейм свободен».

Регистрация и редактор профиля используют `/api/auth/username-availability`.
Auth-api проверяет формат и уникальность через `AccountService`; ответ содержит
только нормализованный `username` и `available`, с `Cache-Control: no-store`.
Проверка предварительная: параллельная регистрация всё ещё может дать 409 при
сохранении. Текущий никнейм в редакторе собственного профиля допустим без запроса.
