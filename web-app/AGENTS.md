# Frontend

Действуют также [корневые инструкции](../AGENTS.md). Все npm-команды ниже - из `web-app`.

## Устройство

- `src/api/` - HTTP-клиент и запросы.
- `src/models/` - типы DTO backend.
- `src/app/` - маршруты и текущий пользователь; `src/hooks/` - общие хуки.
- `src/components/ui/` - базовые элементы, `widgets/` - составные блоки,
  `layouts/` - каркасы, `pages/` - страницы.
- `src/styles/` - глобальные стили и токены.
- `src/utils/` - общие функции.
- `nginx.conf`, `vite.config.ts` - production и dev-прокси.

## Изменения

Переиспользуй существующие компоненты и стили. Запросы размещай в `api/`,
а не дублируй `fetch` по страницам. Сохраняй маршрутизацию `/api` через
общий клиент; не вшивай внутренние Docker-адреса в браузерный код.
Сверяй типы и обработку ошибок с backend. Учитывай загрузку, пустой результат,
ошибки и отмену запросов.

## Запуск и проверки

`npm ci`, затем `npm run dev`. При работающем Docker-стеке для dev-прокси
задай `BACKEND_URL=http://127.0.0.1:8080` в `.env.development.local`.
Dev-сервер: `http://localhost:5173`.

Проверки: `npm test`, `npm run lint`, `npm run build`.
`npm test` запускает Node-тесты API, а не полную проверку интерфейса в браузере.
Для визуальных изменений проверь затронутые страницы вручную, включая узкий экран.
Прокси проверяется из корня: `python web-app/tests/test_proxy.py`; нужен Docker,
тест собирает отдельное окружение. Не редактируй `dist/` вручную.
